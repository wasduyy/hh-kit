# Trae IDE Adapter

## Files Generated

| Source (Template) | Target (Generated) | Purpose |
|---|---|---|
| `.scaffold/adapters/trae/rules-template.md` | `.trae/rules/project_rules.md` | Rules injected into every AI session |
| (auto-generated by init-venv.ps1) | `.trae/mcp.json` | MCP Server registration |

## Rules Generation

The rules template (`rules-template.md`) contains placeholders that are filled during setup:

| Placeholder | Source | Description |
|---|---|---|
| `{{project_name}}` | `.control/harness.yml` → project.name | Project name |
| `{{project_context}}` | `.control/harness.yml` → project.description or manual | Project description |
| `{{coding_principles}}` | `.scaffold/defaults/coding-principles.md` | Coding principles (included inline) |

### Generation Process

1. Read `rules-template.md`
2. Replace `{{project_name}}` from harness.yml
3. Replace `{{project_context}}` with project description
4. Replace `{{coding_principles}}` with content of coding-principles.md (prefixed with `## Coding Principles`)
5. Write to `.trae/rules/project_rules.md`

## MCP Server Configuration

`.trae/mcp.json` is auto-generated by `.harness/scripts/init-venv.ps1`:
- Resolves absolute path to `.venv/Scripts/python.exe`
- Points to `.harness/.scaffold/mcp-server/server.py`
- Uses `cwd` set to project root

## Setup (New Project)

```bash
# 1. Initialize venv + generate .trae/mcp.json
powershell -ExecutionPolicy Bypass -File .harness/scripts/init-venv.ps1

# 2. Generate rules from template
# (Currently manual: copy rules-template.md, replace {{placeholders}})
# Future: CLI tool will automate this

# 3. Restart Trae IDE
```
